# Impeccable Design Context — Tailr

## Design Context

### Users
Tara and Meag — two pet parents sharing a household. They use this app throughout the day for quick, one-tap activity logging (poop, pee, food, sleep, meds) and periodic medical record keeping. Context: phone in hand, often one-handed, sometimes mid-task with a pet. Primary device is mobile (iOS). Speed and reliability matter more than discovery or exploration.

### Brand Personality
**Calm. Caring. Reliable.**

This is a tool for people who love their pets. The aesthetic should feel like a well-designed notebook — quiet, warm, trustworthy. Not a startup dashboard. Not a gamified tracker. A calm companion that stays out of the way until you need it.

### Aesthetic Direction
- **Quiet and warm**: Sage green primary, cream backgrounds, soft shadows — nothing loud
- **iOS-native feel**: Rounded corners, generous touch targets, spring-like interactions
- **Purposeful color**: Pet-specific accent colors add personality without chaos; used sparingly as accents, not backgrounds
- **No dark patterns**: No badges demanding attention, no aggressive CTAs
- **Anti-references**: Avoid neon gradients, heavy glassmorphism stacking, aggressive drop shadows, card-within-card nesting, emoji overload

Direction chosen by user: **quieter** — calmer, more refined, less visual noise.

### Design Principles
1. **Speed over richness** — The primary action (logging) must be reachable in one tap from anywhere. Every extra step costs trust.
2. **Calm by default** — Default state is quiet. Color and motion are rewards for interaction, not ambient noise.
3. **Warmth over polish** — A slightly imperfect, organic feel beats sterile precision. Sage, cream, and rounded forms over sharp corporate geometry.
4. **Context awareness** — One-handed mobile use is the primary case. Touch targets ≥ 44px, no hover-dependent UI, no tiny tap targets.
5. **Trust through consistency** — Same component in every context. No surprise behaviors. Tara and Meag should never have to think about the UI.

### Technical Stack
- Vue 3 + Composition API (`<script setup>`)
- TailwindCSS with custom sage palette + pet-dynamic CSS variables
- Pinia for state
- Firebase Realtime Database
- PWA, mobile-first, dark mode supported
- No charting library yet (weight trends are list-only)

### Current Design System Notes
- **Colors**: `sage-{50-900}` custom scale; pet accent colors via CSS vars (`--pet-color`, `--pet-bg`)
- **Fonts**: Plus Jakarta Sans (display) + Inter (body) — both loaded via Google Fonts
- **Spacing**: 4px base unit, responsive padding via `clamp()` and device-specific breakpoints
- **Touch targets**: 44px minimum enforced
- **Shadows**: Multi-layer `elevation-*` system + color shadows — some redundancy to clean up
- **Cards**: `.card`, `.card-premium`, `.card-glass`, `.card-interactive` — consolidation opportunity
- **Buttons**: `.btn-*` + `.activity-btn-premium` — slightly inconsistent hover behaviors
- **Inputs**: `.input` vs `.input-modern` — unclear primary; standardize on `.input-modern`

### Known Inconsistencies to Address
- Shadow system has redundant variants — consolidate
- Button hover effects slightly different between `.btn-primary` and activity buttons
- Form input class naming (`.input` vs `.input-modern`)
- Typography classes have some redundancy (`.text-h1`–`.text-h6` + `.text-display-*`)
- Pet color theming propagation not always consistent across all components
